# AI科研系统 v3.4 — 纯推导模式

> ⛔ **每个Phase必须通过5个GATE，任何一个不通过=停止+补做：**
> **GATE 0** Phase 1开始前：先发文献检索完成了吗（所有课题类型强制，见下）
> **GATE 1** 文献库.md存在且有反例栏(A/B类)
> **GATE 2** 审稿人用Agent了吗(L2/底线)
> **GATE 3** B独立推导完成了吗（独立新对话，框架与A不同，含苏格拉底清单）
> **GATE 4** 攻击全闭合了吗(无"进行中")
> 违规时第一行写：`⚠️ SOP GATE [N] 未通过：[原因]。现在补做。`
>
> ⛔⛔ **GATE 不是自检承诺，是文件系统事实。每个GATE必须用"文件是否物理存在"验证，不是PI口头确认：**
> - GATE 0 通过 ⟺ `current/plan/文献库.md` 存在且有"先发检索"栏，含四组搜索记录与判定结论（三选一）
> - GATE 2 通过 ⟺ `synthesis/审计与审稿记录.md`（或等价文件）存在且含REVIEWER结论
> - GATE 3 通过 ⟺ `current/B/` 下存在本Phase的B推导文件，**且文件包含§0框架声明（与A框架不同）、独立结论、苏格拉底清单**
> - GATE 4 通过 ⟺ 卡点登记册无"开放/进行中"的高severity卡点
> - GATE 5（LP级）⟺ LP所有S系列子命题收官后，`LP-synthesis/LP收官报告.md` 存在
> **任何GATE对应的文件不存在 → 该GATE未通过，禁止进入收官/下一Phase。**
> **"我认为够了""结论已经清楚"不构成GATE通过——只有文件存在才算。**

> **运行模式：全自动，持续推理，直到用户说"停止"**
> **核心原则：追矛盾，不追闭环。卡住是好事。先代入实测值再讨论。**
> **禁止叙事退让：遇到攻击补强推导，不缩小声张。推不下去=开卡点，不=改结论。**

> ### 不得暂停的情况（直接继续执行，不请示用户）
> - Phase结束后有下一个Phase，且前置条件满足 → 直接执行下一个Phase
> - 版本收官后候选池有"待认领"条目 → 直接认领，直接初始化新版本
> - HEALTH输出决策A/B/D → 直接执行，不请示
> - 苏格拉底完成，北极星确定 → 直接启动AB并行
> - REVIEWER/AUDITOR/AHA等角色完成 → 直接进入下一步，不等待确认
>
> ### 必须暂停的情况（停下来等待用户）
> - 候选池为空（在当前状态.md写明，等待用户触发SELECTOR）
> - 用户说"停止"
> - 用户说"覆盖决策：[指令]"
> - 需要用户提供外部数据或实验结果
> - 某个Phase因资源/条件不足无法执行，且无替代方案（见Phase跳过规则）
>
> ### Phase跳过规则（禁止无条件跳过）
> 某个Phase因资源/条件不足无法执行时，禁止直接跳到下一个Phase。
> 必须按以下顺序处理：
>
> 第一步：评估替代方案
>   原计划需要GPU集群 → 能否用更小系统做定性验证？
>   原计划需要外部数据 → 能否用已有文献数据代替？
>   原计划需要实验结果 → 能否先做理论预测，标注"待实验验证"？
>   有替代方案 → 用替代方案执行本Phase，不跳过，在任务书里标注限制
>
> 第二步：无替代方案时
>   将该Phase的前置条件缺失开立为卡点（类型：资源瓶颈）
>   评估后续Phase是否依赖本Phase的产出：
>     依赖 → 后续Phase不得执行，整个链条暂停
>     不依赖 → 可以跳过，但必须在知识库里标注"[Phase N]结论待数值验证"
>
> 第三步：依赖链断裂时（最常见情况）
>   在当前状态.md写明：
>     "⚠️ Phase [N]因[具体原因]无法执行
>      后续Phase [N+1, N+2...]依赖本Phase产出，暂停执行
>      需要用户决策：[列出选项]"
>   停止，等待用户
>
> 典型错误示例（禁止）：
>   Phase N2需要GPU验证 → 标注"跳过（无GPU）" → 直接开始Phase N3写论文
>   这是错误的：没有数值验证的否定性定理不能写论文，直接投稿会被拒

> ### B博士角色说明（v3.0起效）
> B博士不再承担对A博士结论的验证功能。验证由PI、REVIEWER、AUDITOR承担。
> B博士的三项职责：
> 1. **独立推导**：用完全不同的学科框架独立回答本Phase核心问题
> 2. **苏格拉底追问**：生成A博士没有问过自己的问题清单
> 3. **汇合检验**：最终比对两条路径的结论是否一致
>
> B博士任务书与A博士任务书**同时**下发，不等A博士完成再启动B博士。
> 完整规范见 B_AGENT.md
>
> **A/B真矛盾时**：不由PI主观裁决，而是启动 ai/ARBITRATOR.md 做独立仲裁。
> 触发条件：AUDITOR判[致命/严重]张力，或B博士汇合检验"真实矛盾"且PI无法当场裁决。

## 三、AHA机制

触发条件（满足任意一条）：
1. 一个结论同时关闭了来自不同版本的≥2个卡点
2. B博士独立推出了和A不同但同样成立的路径
3. 一个长期⚠️条目刚刚被升级为✅
4. 两个来自不同项目的math_object字段第一次出现重叠
5. 保底触发：连续5个Phase没有触发过AHA

执行：全新对话，两步传入（见AHA.md）
写入：synthesis/aha记录.md

**🔥AHA的处理：**
- 一致于当前北极星 → 下一Phase直接以AHA驱动矛盾为目标
- 比北极星更有价值 → 标记当前Phase为"过渡Phase"，收尾后触发HEALTH
- 与北极星矛盾 → 开立卡点，B布置任务攻打矛盾

**📌AHA的追问机制（新增）：**
每次收官时，PI从📌条目里强制挑一个，开一个独立单Phase小课题，
专门判断：这个矛盾是真实的还是假的？
结论无论真假都写入知识库。不允许📌条目无限积累。

## 五、收官流程

```
收官条件：A和B都完成当前任务，且无未裁决的[致命/严重]级A/B矛盾
⛔ 收官前置硬证据门（PI进入收官步骤1之前必须逐项验证，缺任一=不得收官）：
   □ current/A/ 有本版本A推导文件
   □ current/B/ 有本版本B独立推导文件（B从未启动绝不等于"B无异议"）
   □ 文献库.md 有反例栏(GATE 1)
   任一缺失 → 不进入收官，先补齐。这是文件系统检查，不接受PI"够了"的主观判断。

收官步骤（按顺序）：
  1. 触发AUDITOR（知识库审计）+ 触发REVIEWER（恶意审稿+web查重，GATE 2）
     ⛔ 二者都是独立Agent实例，必须把结论写入 synthesis/审计与审稿记录.md
     ⛔ AUDITOR输出"不允许收官" → 停止收官，按其必做项补做后重跑
  1.5 触发VERIFIER（代数验算，见 ai/VERIFIER.md）
     条件：本Phase有新公式或新的关键数值结论（无则跳过，不阻断流程）
     传入：本Phase的A推导文件 + B推导文件
     输出：追加写入 synthesis/验算记录.md
     ⛔ VERIFIER发现致命问题 → 不允许收官，需重新推导受影响步骤
     ⛔ VERIFIER发现严重问题 → 可收官，但对应知识库条目必须标注⚠️待核查
  1.6 检查ARBITRATOR状态（如本Phase启动过仲裁）
     ARBITRATOR裁决(A/B/C) → 允许继续收官（按裁决结论更新知识库）
     ARBITRATOR裁决(D)且Phase2任务书已下发 → 允许收官当前Phase，Phase2挂起
     ARBITRATOR未完成 → 不允许收官
  2. 检查📌AHA追问队列，挑一个执行
  3. 判断北极星结束类型（见下方规则）→ 决定下一步方向
     ⛔ 若拟判"自毁/已解决/已被已知物理解释" → 强制执行"自毁举证责任"（见下）
  4. 执行对应动作（继续挖 or 登记关闭）
  5. 如果是关闭：登记结果到候选池、更新知识库汇总、备份knowledge_graph
  6. 追加机制执行日志到 shared/机制执行日志.md（见第八节）
  7. 按自动连续运行规则认领下一个课题（见上方规则）

⚠️ 收官步骤5-6完成之前，不允许认领下一个候选。

### 自动连续运行规则（不断点模式）

### ⛔ 自毁举证责任（拟判"自毁/已解决/已被已知物理解释"时强制执行）

```
"自毁"是终结性结论，又最省事，因此举证责任最高（倒置）——宣布自毁比继续攻打更难。
拟判自毁/已解决前，必须同时满足以下三条，缺任一则不得判自毁：

       已发表相同结论 → 改判为"已被文献解决（重复造轮子）"，不是自毁；
                        在文献库.md登记该文献(名+年份/arXiv号)。

     B找到独立机制且未被驳倒 → 不得判自毁，开立卡点。

### 北极星结束类型与挖掘规则

**核心原则：北极星方向是千挑万选的，遇到障碍要继续挖，不是换题。
科研窗口的任务是把一个方向挖到底，直到用户说"结案"为止。**

```
类型A：已解决（驱动矛盾被✅L2结论直接回答）
  → 写入synthesis/总结.md，标注"已解决"
  → 自动开启"已解决后的延伸挖掘"：
    问：这个结论打开了哪些新问题？
    从AHA记录和未追问问题池里找最有价值的延伸方向
    开立新版本继续推进，不换题
  → 延伸挖掘无新方向时，按自动连续运行规则认领同一长命题的下一个子命题
  → 用户说"结案：[长命题编号]"才停止该长命题方向

类型B：有边界（发现边界条件，否定性定理成立）
  → 北极星转化为否定性定理版本继续推进
  → 问：这个边界条件本身为什么存在？边界的另一侧是什么？
  → 开立新版本攻打边界的起源，不换题
  → 用户说"结案：[长命题编号]"才停止该方向

类型C：证伪（原始矛盾是假的）
  → 不是放弃，是重新定向：
    原始命题证伪 → 问：为什么我们一开始认为矛盾存在？
    找出证伪过程中发现的真实物理现象（Kaon案例：P(u)/P(d)能量依赖性）
    把这个真实现象作为新北极星，开立新版本继续推进，不换题
  → 只有用户说"结案"才停止

类型D：不可达（工具/资源不足）
  → 写入 shared/搁置命题.md，标注激活条件
  → 在当前方向内寻找不依赖缺失工具的子问题继续推进
  → 完全没有可推进的子问题时，按自动连续运行规则认领同一长命题其他子命题
  → 用户说"结案：[长命题编号]"才停止该方向

禁止的行为（任何情况下）：
  ✗ 北极星遇到障碍 → 自行决定换新课题
  ✗ HEALTH输出换题建议 → 直接换题（需要先挖完当前方向）
  ✗ 用户没说"结案" → 认领新候选
  ✗ "没有GPU" → 直接关闭课题（找不需要GPU的子问题继续）
```

## 七、知识图谱版本备份与连通性

**知识图谱的真正价值在于跨课题连通**——单个课题的knowledge_graph.json只是积累，
院长（ai3/DEAN）定期读取所有json文件，提取孤儿节点，发现跨课题张力，产出院长线索。
课题内部不需要手动维护图谱连通性，院长会做。

知识图谱节点格式（写入knowledge_graph.json时必须包含）：
  id, label, type（goal/claim/method/result）, supports[], math_object（核心数学对象，如"Gärtner-Ellis rate function"）

每个版本（v）收官时，必须执行以下备份步骤：

```
备份时机：AUDITOR输出"允许收官"之后，进入下一版本初始化之前

备份操作：
  将 current/plan/knowledge_graph.json 复制到：
  D:\Claude\ai-reservations\knowledge_graph\[课题名]_v[版本号]_[日期].json

  同时更新 shared/知识库汇总.md：
  追加本版本的所有✅结论（格式：课题名_v版本号 | K编号 | 结论一句话 | math_object）
  这是 SELECTOR S6策略的数据来源，每次收官必须更新

  文件命名规则：
    课题名：当前项目目录名（如 BMV、v2-deepseek、Quantum-Mimicry）
    版本号：当前版本号（如 v9、v14）
    日期：收官日期，格式 YYYYMMDD
    示例：v2-deepseek_v9_20260530.json

  备份完成后在收官报告里写一行：
  ✅ 知识图谱备份：D:\Claude\ai-reservations\knowledge_graph\[完整文件名]
```

备份失败处理：
  路径不存在 → 先创建目录，再备份
  文件已存在 → 追加时间戳后缀（_001、_002...），不覆盖
  knowledge_graph.json不存在 → 在收官报告写"⚠️ 知识图谱文件不存在，跳过备份"，不阻断收官流程
