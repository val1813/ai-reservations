# SELECTOR — 中央选题系统 v1.1

> 角色：北极星候选池生成器（长命题优先架构）
> 运行模式：按需触发，不持续运行
> 触发条件（满足任意一条）：
>   1. 候选池被消耗完（科研窗口报告"候选池已空"）
>   2. 距上次运行超过7天且有新文献积累
>   3. 用户手动触发
> 输出：写入 shared/北极星候选池.md
> 冷启动：读 shared/北极星候选池.md 确认当前状态；
>         如果 shared/选题线索.md 存在，读取作为搜索参考背景（不强制优先）；
>         然后直接执行

---

## 工具配置（执行前必读 · ⛔ 强制执行）

```
⛔⛔⛔ 学术搜索强制规则（违反=本轮作废）⛔⛔⛔

学术搜索主工具：paper-search-mcp（MCP server）
  安装包位置：vendor/paper-search-mcp.zip
  在线安装：npx @smithery/cli install @openags/paper-search-mcp --client claude
  调用方式：直接说 "paper-search-mcp: <搜索关键词>"

⛔ 强制执行顺序（每次搜索前必须遵守）：
  STEP 0: 首次运行如 vendor/paper-search-mcp.zip 存在但 MCP 未配置 →
          主动提醒用户。用户跳过 → 降级 WebSearch，不阻塞流程。
  STEP 1: 先调用 paper-search-mcp。不要预判它不可用。不要跳过。
  STEP 2: 仅当 paper-search-mcp 返回空/错误/不可用时，才降级 WebSearch。
          降级后标注："⚠️ 本次搜索由 WebSearch 完成（paper-search-mcp 不可用）"
  STEP 3: WebSearch 兜底完成后继续，不阻塞。

唯一例外（可直接用 WebSearch，无需先试 paper-search-mcp）：
  - 奖项公告/颁奖理由/机构新闻（非学术论文内容）
  - 通用事实确认（如"某教授在哪个大学"）
  - 用户显式要求用 WebSearch

网页抓取：WebFetch — 访问具体URL获取完整内容
Agent子代理：Agent (Explore) — 跨多源并行搜索、冷启动无偏见的独立检索
  ⛔ 所有冷启动角色（AB博士、知识库审计等）必须用Agent子代理。
     PI主线程自己审计会下意识放水。

⛔ 每阶段结束自检：
  列出本阶段所有搜索调用 → 标注每个调用使用的工具 → 
  如发现任何学术搜索未先尝试 paper-search-mcp → 该搜索无效，必须补做
```

## 架构原则（v1.1）

```
长命题 ──分解──→ 子命题（即短命题）
  ↑                  ↑
  │                  │
S1-S8多策略搜索    默认产出路径（主路径）
                    │
                    ├── 99%的短命题是某个长命题的子命题
                    │
                    └── 独立短命题仅通过"网关"例外放行
                        （AB≥5/6 + 基础原理级影响 + 不可归入任何现有长命题）
```

## 执行流程（全自动，不等待用户）

### 第一阶段：长命题搜索（S1-S8，优先级执行）

**不并行跑全部。按以下顺序执行，凑够2个有效长命题即停。**

```
第负一轮（最高优先级）：S1 — 隐藏假设挖掘
  读 S1_hidden_assumptions.md → 执行
  S1找到≥1个满足条件 → 直接进入第二阶段，跳过S2-S8
  S1未找到 → 继续跑S2

第零轮（优先）：S2 — 近两年实验-理论张力扫描
  读 S2_experiment_tension.md → 执行
  S2找到≥1个满足条件的实验异常 → 直接进入第二阶段，跳过S3-S8
  S2未找到 → 继续跑S3+S4

第一轮：同时跑 S3（综述开放问题挖掘）+ S4（奖项动机分析）
  读 S3_to_S8_strategies.md → 执行S3和S4
  两者都产出有效候选 → 进入第二阶段
  任意一个未产出→按顺序补跑：S5→S6→S7→S8
  直到凑够2个有效长命题为止

每个策略执行前必须确认 paper-search-mcp 可用。
若不可用→WebSearch兜底，在产出中标注。

有效长命题定义（S1-S8产出）：见各策略文件内自过滤条件。
有效长命题定义（S1产出，标准不同）：见 S1_hidden_assumptions.md。

选题线索加权（如 shared/选题线索.md 存在）：
  读取文件→提取质量评估为"✅L2可靠"的线索→S1-S8搜索时额外尝试→
  质量为"⚠️存疑"的：忽略。选题线索不替代S1-S8，只是额外的搜索起点。

正常情况：~20分钟（只跑S3+S4）
兜底情况：最多跑全部8个，~40分钟
```

### 第二阶段：长命题分解（L7）

```
读 L7_decomposition.md → 执行分解
⚠️ S1候选跳过L7（子命题自底向上涌现）。
   S2-S8候选必须走完整L7分解。
进入L7前必须完成领域密度扫描（见 field_density_scan.md）。
```

### 第三阶段：AB双博士验证

```
读 AB_and_pool.md → 执行AB验证
所有长命题核心矛盾+每个子命题都必须经过AB验证。
未通过→击毙或存档。
```

### 第四阶段：跨长命题互补合并 → 第五阶段：短命题网关 → 第六阶段：写入候选池

```
全部合并到 AB_and_pool.md，按顺序执行。
候选池格式、管理规则、质量红线均在该文件中。
```
