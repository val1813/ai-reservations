## §0 框架声明：为什么是π-calculus

A博士会走范畴论Process Theory + Petri网的路线。GATE 0已经替他铺好了。Petri网的token消耗、event structures的偏序因果、Kissinger-Uijlen (2017)的统一框架——这是学院派的完美答案。

我不走这条路。

我选**π-calculus (Milner, Parrow, Walker 1992; Milner 1999)**——移动进程的演算。理由粗暴直接：

**π-calculus是唯一一个"事件顺序+资源消耗+名字传递"三者都是built-in原语的数学框架。**

别的框架需要把这三样东西分别编码进去——Petri网有token但没有名字传递，范畴论有组合但没有原生并发语义，资源论有序关系但没有通信。π-calculus一个语法就全有了。

更关键的是：π-calculus的**bisimulation等价**给了Aporia一个它最需要但一直缺少的工具——判断两个物理理论是否"行为等价"的严格准则。DGF声称从A1+A2导出牛顿引力，但"导出"是什么意思？如果两个理论在所有观测上一致但在未观测处不同，它们算同一个理论还是两个？Bisimulation回答了这个问题：它们在观测上不可区分当且仅当它们是bisimilar的。

### 为什么不选另外两个选项

**代谢网络/FBA:** 化学计量矩阵S·v=0确实漂亮。格点=代谢物，determination=酶促反应，容量约束=化学计量。但FBA是个**稳态**框架——它告诉你通量分布的可行空间，不告诉你通量怎么随时间达到稳态。我们要的恰恰是"怎么从静态鸽巢计数过渡到动态事件统计"——FBA把动态压缩成了稳态约束，把我们要桥接的gap压没了。FBA解决的是另一个问题。

**扩展式博弈:** 博弈树的原生顺序结构是真货。信息集对应DGF的"未确定"格点。但博弈论的"资源消耗"需要额外编码——你需要把payoff翻译成资源，把策略选择翻译成determination事件。这不是built-in的，是隐喻。而且博弈树的"回溯归纳"依赖于**所有玩家知道博弈树结构**——这个共同知识假设在物理约束系统中没有对应物。格点不知道DAG的全局结构。

**π-calculus**胜出因为它的三个原语——并行组合(|)、通信前缀(input/output)、名字限制(ν)——恰好覆盖了DGF需要的三个操作：格点可以同时存在(|)、determination=通信事件、资源=被传递和消耗的名字。没有比喻，全是结构对应。

## §1 原框架的核心结构

### 1.1 π-calculus语法

π-calculus的语法出奇地小。进程P由以下语法定义：

```
P ::= 0                           (空进程，终止)
    | P₁ | P₂                     (并行组合)
    | π.P                         (前缀：执行动作π然后变成P)
    | P₁ + P₂                     (选择：执行P₁或P₂)
    | νx.P                        (限制：创建新名字x，作用域为P)
    | !P                          (复制：无限多个P的并行副本)
    | [x=y]P                      (匹配：如果x=y则变成P)

π ::= x̄y                          (输出：在通道x上发送名字y)
    | x(z)                        (输入：在通道x上接收名字，绑定到z)
    | τ                           (静默动作：内部计算/同步)
```

就这11行。整个移动并发计算的理论建立在这11行上。

### 1.2 核心概念拆解

**进程 = 并发执行的原子动作序列。** 一个进程不是"状态的函数"，而是一个"可能行为树"。P | Q意味着P和Q同时存在，独立演化。

**名字 = 资源 + 通道 + 身份。** 名字在π-calculus中身兼三职：
- 名字是**通信通道**——通过它发送和接收其他名字
- 名字是**资源**——被创建(νx)、被传递(在x上发送y)、被消耗(接收后绑定)
- 名字是**身份**——两个进程共享一个名字意味着它们可以通信

这个三重身份是π-calculus最深的洞见：**资源、通信能力和身份是同一个东西的不同表现。** 这对DGF有直接含义——格点的"determination状态"、格点间的"信息流"和格点的"可区分性"可能也是同一个东西。

**名字的创建(νx.P) = 资源生成。** νx创建一个新的、全局唯一的的名字x。作用域为P——x只在P内部及其通信对方可见。这直接对应DGF中"信息被创建在某个格点"。

**名字的传递(在通道a上发送b) = 资源转移 + 通道能力的委托。** 当P执行āb.Q，它将b发送到通道a上。收到b的进程现在拥有了b——可以进一步传递它、在它上面通信、或用它做匹配。这既是"信息流动"（b的内容被传递了）也是"资源消耗"（发送方不再独占b——在多数编码中，发送后P继续持有b的能力被Q的行为决定）。

**名字的接收(a(x).P) = 资源消耗 + 绑定。** 接收方将接收到的名字绑定到x，然后在P中使用x。这消耗了"在a上等待"的能力，获得了使用x的能力。

### 1.3 操作语义（Reduction Semantics）

π-calculus的操作语义由**结构同余(structural congruence)**和**归约规则(reduction rules)**定义。结构同余≡是最粗的等价——它识别语法上不同但行为上不可区分的进程：

```
P | 0 ≡ P                       (0是并行的单位元)
P | Q ≡ Q | P                   (并行交换)
(P | Q) | R ≡ P | (Q | R)       (并行结合)
νx.0 ≡ 0                        (空限制无用)
νx.νy.P ≡ νy.νx.P              (限制交换)
νx.(P | Q) ≡ P | νx.Q  if x ∉ fn(P)  (作用域挤出)
!P ≡ P | !P                    (复制展开)
```

**唯一的计算步——通信(Tau)归约：**

```
x̄y.P | x(z).Q  →  P | Q{y/z}
```

即：在通道x上，发送方发送y，接收方将y绑定到z，然后双方各自继续。**这是计算发生的唯一方式。** 没有赋值、没有全局状态、没有时间步进——只有名字在通道上的流动。

### 1.4 为什么不假设时间

π-calculus**没有时钟**。进程演化的唯一驱动力是通信同步：一个输出和一个匹配的输入在同一个通道上相遇→它们同步→双方继续。没有"先发生"和"后发生"的全局概念——只有"这个通信发生在那个通信之前"的**因果偏序**。

这是关键。π-calculus中的"事件顺序"完全由通信的因果依赖定义：
- 如果P必须接收到名字x才能执行输出x̄y，那么"接收x"因果先于"输出x̄y"
- 如果P和Q在并行中各自独立演化，它们的事件是**并发**的——没有顺序关系
- 因果偏序 ≠ 时间顺序。因果偏序是**偏的**(partial)——有些事件对没有因果顺序，它们就是并发的

这与DGF需要的东西精确对齐：DGF需要一个"事件按顺序发生"的概念，但这个顺序不应该是预设的时间参数t。π-calculus的因果偏序——由名字依赖定义的偏序——恰恰满足这个要求。

### 1.5 Bisimulation — 行为等价的形式准则

π-calculus最强大的工具是**bisimulation**（互模拟）。两个进程P和Q是bisimilar的（记为P ~ Q）当：

**定义（强互模拟）:** 一个二元关系R是强互模拟，如果对任意(P,Q) ∈ R和任意动作α：
- 如果P →^α P'，则存在Q'使得Q →^α Q'且(P',Q') ∈ R
- 如果Q →^α Q'，则存在P'使得P →^α P'且(P',Q') ∈ R

直观：两个进程是bisimilar的当它们可以互相模拟对方的所有动作，且模拟后仍然保持可互相模拟。**任何外部观察者无法区分bisimilar的进程。**

**弱互模拟(≈):** 忽略内部动作τ。P ≈ Q当它们在外部可观测动作上互相模拟。这是"观测等价"的正式定义。

**对Aporia的关键意义:** 两个物理理论T₁和T₂是"观测上等价的"当且仅当它们作为π-calculus进程是弱互模拟的。Bisimulation给了Aporia一个**严格的操作准则**来判断"两个理论是否可区分"——比A博士的Hausdorff距离更贴近操作实践，比模型论的初等等价更细粒度。

## §2 映射到DGF

### 2.1 核心映射表

| DGF概念 | π-calculus对应 | 精确定义 |
|:--------|:---------------|:---------|
| **格点 (lattice site)** | **进程P_i** | 每个格点是一个并发进程，有自己的名字空间和可能的通信 |
| **Determination (格点状态确定)** | **通信事件(τ-归约)** | 两个格点通过共享通道同步→信息被传递→接收方格点的状态被"确定" |
| **资源/信息容量** | **名字** | 名字=可被传递、复制、消耗的资源单元。νx创建新名字=信息被生成 |
| **资源消耗** | **名字的接收绑定** | a(x).P中，x被绑定→这个接收能力被消耗，P获得了使用x的能力 |
| **容量约束(I(x)∈[0,1])** | **名字空间大小上界** | 一个进程可访问的名字数是其在通信中可获得的名字的集合大小 |
| **前向转移(forward transfer)** | **输出动作x̄y** | 在通道x上发送资源y→信息从发送方流向接收方 |
| **回流(reflux)** | **反向通信** | 接收方在接收后通过另一通道发回信息→信息反向流动 |
| **因果依赖(C(x,y))** | **名字依赖** | 如果P需要名字x来执行动作，且x由Q产生，则Q因果先于P |
| **鸽巢原理** | **名字作用域的线性逻辑** | νx.P中的x是线性的——每次使用后作用域受限。名字的创建和消耗遵循线性逻辑 |
| **DAG结构** | **进程的静态拓扑** | 进程的并行组合结构定义了谁可以与谁通信——这是静态的"通道连接图" |
| **P_reflux** | **反向通信事件/总通信事件** | 在所有τ-归约中，反向信息流(从接收方回到发送方或其前驱)的比例 |

### 2.2 格点 ↔ 进程

每个DGF格点i被编码为一个π-calculus进程L_i：

```
L_i = νs_i.(!R_i(s_i) | !D_i(s_i))
```

其中：
- s_i是格点i的**私有名字**——代表格点的"状态"（未被确定的信息）
- R_i(s_i)是格点i的**接收者行为**：在输入通道上等待信息，收到后更新状态
- D_i(s_i)是格点i的**发送者行为**：在其状态确定后，向相邻格点发送信息

关键：s_i的创建(νs_i)是**线性的**——s_i只存在于L_i的作用域内。当s_i作为名字被发送给另一个格点时（通过输出），s_i被"共享"了——这对应DGF中信息从一个格点流到另一个格点。接收方格点现在可以访问s_i，意味着它的"被确定状态"包括了格点i的信息。

### 2.3 Determination ↔ 通信同步

在DGF中，determination是"格点的状态被确定为一个具体值"的事件。在π-calculus中：

```
determination事件 = 输入接收动作 a(x).P 被触发
```

当一个格点L_j执行a(x).P，它在通道a上等待。当另一个格点L_i执行āv（在a上发送名字v），同步发生：
```
āv.Q | a(x).P  →  Q | P{v/x}
```

L_j现在绑定了名字v——它的状态从"未确定"（在a上等待）变成"确定"（获得了v）。这正是determination：一个格点通过从已确定的相邻格点接收信息来获得确定状态。

**并发determination = 并行同步：**
```
āv.Q | a(x).P | b̄w.R | b(y).S  →  Q | P{v/x} | R | S{w/y}
```
两个determination事件同时发生（在因果偏序意义下是并发的）。

### 2.4 资源消耗 ↔ 名字的线性使用

DGF的核心运作约束是：**一个token被消耗后不能被再次使用。** 在π-calculus中，这对应名字的**线性行为**。

名字在π-calculus中天生具有"可被消耗"的语义——虽然标准π-calculus中名字可以被复制（通过多次输出），但存在**线性π-calculus**变体（Kobayashi, Pierce, Turner 1999），其中名字的类型系统强制执行：每个名字在其生命周期中最多被使用一次作为输入。

在线性π-calculus中：
```
νx.(āx | a(y).b̄y | a(z).c̄z)  →  类型错误！x被输入了两次
```

这精确对应DGF的约束：一个token不能同时被两个格点消耗。线性名字 = 受限资源。

**对Aporia的一般化：** 即使不用线性π-calculus，标准π-calculus中的名字作用域机制已经编码了"消耗"的弱形式。当一个名字x被创建νx.P，一旦所有拥有x的进程都终止或不再使用x，x就从系统中消失了——被"消耗"了。名字的生命周期 = token的生命周期。

### 2.5 容量约束 ↔ 名字空间边界

DGF的容量约束C1："每个格点的信息容量≤1 bit"。在π-calculus中：

一个进程的**名字空间(namespace)**是该进程在任何可达状态下可以访问的名字集合。名字空间的大小 = 进程可以区分的不同"信息单元"的数量。

容量约束翻译为：**对格点L_i，其名字空间的大小≤2（对应1 bit：可以处于两种可区分状态之一）。**

```
容量约束C1: |fn(L_i) ∪ bn(L_i)| ≤ 2
```
其中fn是自由名字集（已知的通道），bn是绑定名字集（已接收的信息）。

这个约束在π-calculus中可以被**类型系统**强制执行：声明每个格点进程最多有两个名字——一个是其"自身状态"名字，一个是从邻居接收的名字。

### 2.6 回流 ↔ 反向通信事件

在DGF中，回流(reflux)是"信息从已确定的格点回流到上游已确定格点"——本质上违背了因果有向性。

在π-calculus中：如果格点A向格点B发送了名字（A→B），然后B通过某个通道向A发送了另一个名字（B→A），这第二个通信是**反向的**——信息从"下游"回流到"上游"。

更精确地，回流事件 = 通信图中**闭合有向环**的出现。在因果偏序中，如果存在事件e₁（A向B发送）和e₂（B向A发送），且e₁因果先于e₂，则这个双向通信构成了回流的π-calculus对应。

**P_reflux的π-calculus定义：**
```
P_reflux = Pr[在观测窗口内，存在通信对(x̄y, ūv)使得：
    sender(x̄y) = receiver(ūv) = A 且
    sender(ūv) = receiver(x̄y) = B 且
    x̄y 因果先于 ūv]
```

即：在观测窗口内，双向通信事件的比例。

## §3 静态→动态桥的证明草图

### 3.0 问题重述

DGF目前的鸽巢原理推导给出了P_reflux的一个**静态上界**：

```
P_reflux ≤ 1 / (1 + N_forward / N_reverse)
```

这个推导是纯计数：统计满足鸽巢约束的配置数 → 推导配置空间的比例上界。

**Gap:** 这计算的是"可能配置的比例"，不是"在动态演化中实际观测到回流事件的频率"。静态计数假设每个配置等概率地被访问——这在动态系统中通常不为真。**我们需要证明：在合理假设下，静态的比例上界也是动态的频率上界。**

### 3.1 定理陈述（非正式）

**主张:** 在DGF约束系统被编码为π-calculus进程后，以下成立：

> 如果(1) 每个格点的名字空间≤2（容量约束），(2) 通信受因果偏序约束（无预设时间），(3) 系统的通信图是定义在格点邻接关系上的DAG的传递闭包——则P_reflux的长时间频率 ≤ 静态鸽巢界 + ε(N)，其中ε(N)→0当格点数N→∞。

### 3.2 证明草图

**Step 1: 将DGF约束系统编码为π-calculus进程网络**

定义进程网络 `Net(N, E)`：
```
Net(N, E) = ν(ch_{ij})_{(i,j)∈E}. ( |_{i=1..N} L_i({ch_{ij}}_{j∈neighbors(i)}) )
```

其中：
- N个格点，每个是进程L_i
- 通道ch_{ij}连接格点i和j（对应DAG中的有向边i→j）
- L_i的私有名字空间 = {s_i} ∪ {ch_{ij} | j∈neighbors(i)} ∪ {接收的名字}

**容量约束翻译为类型系统约束：**
```
∀i: |namespace(L_i)| ≤ 2 + deg(i)
```
其中deg(i)是格点i的邻居数。2来自私有名字s_i+接收缓冲，deg(i)来自邻接通道。

**Step 2: 定义进程的迹语义（Trace Semantics）**

考虑进程网络的归约序列：
```
Net(N, E) = P₀ →^τ P₁ →^τ P₂ →^τ ... →^τ P_k →^τ ...
```

每一步τ-归约对应一个通信事件——即一个determination事件。定义迹：
```
trace(Net) = e₁, e₂, e₃, ...
```
其中e_k = (sender_k, receiver_k, channel_k, name_k)是第k步通信。

**定义回流事件：**
事件e_k是回流事件，如果存在一个更早的事件e_j (j < k)使得：
- sender(e_k) = receiver(e_j)（发送方是被更早事件的接收方）
- receiver(e_k) = sender(e_j)或receiver(e_k)在sender(e_j)的因果上游

即e_k将信息发送回了它的来源方向。

**定义频率：**
```
f_reflux(T) = |{e_k : k ≤ T, e_k是回流事件}| / T
```

**Step 3: 鸽巢原理的进程论翻译**

在π-calculus中，每个名字的传播受其作用域约束。一个名字x由νx在某个格点A创建。当A通过输出x̄y将x（或x作为通道传递）发送给B时，x的作用域扩展到包含B。B现在可以使用x。

**关键观察：** 名字的传播图是原始DAG的子图（在传递闭包下）。如果DAG是传递的且无环的，则名字不能回到其创建者——因为那需要DAG中的反向边。

**进程论鸽巢原理：**
> 设名字x由格点A创建。设可以访问x的格点集为Reach(x)。任意时刻，如果x是"活跃的"（至少一个持有者尚未终止），则|Reach(x)| ≤ 1（在容量=1 bit的约束下——每个名字被至多一个格点作为"当前状态"持有）。
>
> 一旦x被传递到B，A失去了对x的独占（在容量约束下），x不再在A的"活跃名字空间"中。

这意味着：**名字的"被持有"状态图是一组有向路径，每条路径从创建者开始，在消费者处结束。路径不能折返——因为DAG无环。**

**Step 4: 从名字传播路径推导回流事件的边界**

回流事件对应于名字传播路径上的**折返**——某些名字逆着DAG的方向传播回来。

在容量约束下（每个格点至多持有2个名字），考虑所有可能的名字传播路径配置：
- 前向路径（顺DAG方向）的数量 ≤ 总通信事件数
- 回流路径的数量 = 折返事件的数量

**鸽巢论证（进程论版本）：**
每个格点i有容量2（至多同时持有2个名字）。设格点i的前向输出次数为f_i，反向输出次数为r_i。由于每个通信事件消耗发送方持有的一个名字（容量约束：传递意味着让渡），且每个格点最多从邻居接收deg_in(i)个名字：

对于整个系统的长时间平均：
```
∑_i r_i ≤ ∑_i f_i  （鸽巢：反向输出不能超过总持有量）
```

因此：
```
f_reflux = R / (F + R) ≤ F / (F + R) = 1 / (1 + R/F)
```

其中R = 总反向通信次数，F = 总前向通信次数。

如果R/F ≤ 某个关于约束参数的函数，则f_reflux ≤ 1/(1 + const)。这与静态鸽巢的P_reflux ≤ 1/(1 + N_forward/N_reverse)形式一致。

**Step 5: 证明动态频率收敛到静态上界**

需要论证：进程网络的长时间迹中，回流频率以高概率不超过静态鸽巢界。

**论证策略——使用π-calculus的bisimulation和迹等价：**

1. 将进程网络Net(N, E)与其**名字流动图**相关联。名字流动图MFG = (V, E') 其中(i,j)∈E'当名字可以从i流到j。

2. 在容量约束下，MFG是原始DAG(N, E)的子图（可能包含反向边，但这些反向边对应回流）。

3. 考虑Net(N, E)的**所有可能迹的集合**Traces(Net)。定义等价关系：两个迹是等价的如果它们的名字在格点间的传递历史相同（忽略时序，只看因果依赖）。这定义了迹上的**同余关系**。

4. 在同余类上，回流事件的比例R/(F+R)由一个**组合计数**给出——这正是静态鸽巢原理计算的量。不同迹之间的变化（受动态调度影响）只改变F和R的绝对值，但不改变其比例的上界。

5. 因此，对任何单条迹：
```
f_reflux = R/(F+R) ≤ max_{同余类} R/(F+R) = 静态鸽巢界
```

**关键假设（显式声明）：**
- **假设H_B1 (遍历性):** 进程网络的演化访问了所有与因果约束兼容的通信序列。没有这个假设，系统可能被困在某个"非典型"迹中，其回流比例偏离鸽巢预测。
- **假设H_B2 (容量均匀):** 每个格点的名字空间容量确实为2（或某个全局常数）。如果容量随格点变化，鸽巢论证需要调整为按容量加权。
- **假设H_B3 (通信公平性):** 每个格点有平等机会与邻居通信。没有"饥饿"——某些边被无限期推迟通信。
- **假设H_B4 (名字线性使用):** 名字被传递后，发送方不再保留对该名字的独占使用能力。这是令牌传递模型——如果没有这个假设，鸽巢原理不适用（因为"被消耗"没有操作意义）。

### 3.3 与A博士Petri网方案的比较

A博士的Petri网方案和B博士的π-calculus方案共享一些核心结构，但有本质区别。

**共享的：**
1. 两者都使用token/名字作为"资源单元"
2. 两者都通过变迁/通信来模拟资源消耗
3. 两者都有因果偏序（Petri网的occurrence net sequence / π-calculus的名字依赖）
4. 两者都支持并发（Petri网的并发变迁 / π-calculus的并行组合）

**π-calculus多了什么：**

| 特性 | Petri网 | π-calculus | 物理含义 |
|:-----|:--------|:-----------|:---------|
| **名字传递** | 无。Token是不可区分的（除非有色Petri网） | 有。名字本身是数据，可以被传递 | 信息内容(非仅信息量)可以在格点间流动 |
| **作用域机制** | 无。Place的token对所有transition可见 | 有。νx的作用域限制名字的可见性 | 信息可以局域化——对应光锥 |
| **Bisimulation** | 有(bisimulation on Petri nets, van Glabbeek)但不原生 | 原生。π-calculus的bisimulation是一阶概念 | 判断理论等价的操作准则 |
| **通道作为一等对象** | 无。Place→Transition结构是固定的 | 有。通道名字可以被传递——连通性动态变化 | DAG的拓扑在determination过程中可能改变 |
| **移动性** | 静态拓扑(除非自修改网) | 移动。进程的连通性随名字传递而改变 | 格点间的因果连接可以动态创建/销毁 |

**Petri网多了什么：**

| 特性 | π-calculus | Petri网 | 物理含义 |
|:-----|:-----------|:--------|:---------|
| **资源并发计数** | 弱。名字的"数量"不是原生概念 | 强。Token计数是核心 | 容量约束的精确计数更容易 |
| **图形可视性** | 差。进程表达式不直观 | 好。网图直观显示token流动 | 约束的视觉验证 |
| **Unfolding语义** | 无原生unfolding | 有。Occurrence net / unfolding | 将并发展开为偏序——量子事件结构(QPNs 2025) |
| **量子化路径** | 无已知量子化 | 有。QPNs (Joachim et al. 2025) | 量子→经典的Petri网已经存在 |

**互补性评估：**

π-calculus和Petri网不是竞争者——它们是**互补层**。Petri网是"资源计数层"——谁的token在哪，token够不够触发变迁。π-calculus是"信息流层"——什么信息被传递了，传递改变了谁的什么状态。

DGF需要两者：鸽巢原理需要Petri网的token计数（"多少资源"），determination事件需要π-calculus的名字传递（"什么资源——以及它意味着什么状态"）。

**最优策略（B博士的建议）：** 不选一个。用π-calculus定义determination的操作语义和信息流的名字传递，用Petri网（作为底层）定义token的创建/消耗计数。这两层通过一个翻译连接：Petri网的token→π-calculus的名字，Petri网的transition→π-calculus的同步通信，Petri网的place→π-calculus的并行进程。这种**分层混合架构**比单独任一框架都更强——并且A博士不会想到这个组合（他会走范畴论Process Theory的路线，那是第三层——元层）。

## 深挖1：名字挤出(Name Extrusion) —— 从静态计数到动态事件的桥接核心

### 1.1 什么是名字挤出

在π-calculus中，名字挤出(name extrusion)是作用域扩展的操作语义。考虑：

```
νx.(āx.P | a(y).Q)  →  νx.(P | Q{x/y})
```

最初，x的作用域是āx.P | a(y).Q。归约后，x的作用域扩展到包含Q。Q现在可以引用x——x被"挤出"到了Q的作用域中。

**结构同余规则（作用域挤出）：**
```
νx.(P | Q) ≡ P | νx.Q  if x ∉ fn(P)
```

这个规则说：如果P不使用名字x，则x的作用域可以从包含P的上下文"挤出"——只限制Q。

### 1.2 挤出的资源论含义

名字挤出是π-calculus中"资源转移"的形式化。当x从A挤出到B：
- A失去了对x的独占使用（因为作用域缩小了——现在仅限P）
- B获得了使用x的能力（因为作用域扩展了——现在包含Q）
- 之前，B不能使用x（在P | νx.Q中，Q在νx内，但B无法通过x通信——因为x在A的私有作用域中，B不在该作用域中）

**关键：挤出之前和之后的"状态"是不同的——这恰好是determination改变格点状态的操作形式。**

### 1.3 挤出图(Extrusion Graph)

定义：进程网络Net(N, E)的**挤出图**EG = (V, E_extrude) 其中(i,j) ∈ E_extrude当存在一个归约步骤中名字从格点i挤出到格点j。

挤出图与DAG的关系：
- DAG(N, E)定义**可能的**信息流方向（边i→j存在当i可以因果影响j）
- 挤出图EG定义**实际的**信息流——哪些名字实际被传递了

**DAG是静态的。挤出图是动态的。桥接问题的核心就是DAG与挤出图的关系。**

### 1.4 挤出深度与回流

定义挤出深度：名字x的**挤出深度**d_extrude(x)是在其生命周期中被挤出的次数——即被传递的次数。

定义回流挤出：如果名字x从格点i挤出到格点j，且j在DAG中因果先于i（即存在从j到i的有向路径），则这次挤出是**回流挤出**。

**定理（挤出回流界——进程论版本）：**
在容量约束下（每个格点名字空间≤2），任意名字的挤出深度≤|V|（格点总数）。更紧地，如果DAG的深度为D，则任意名字的挤出深度≤D + R_max，其中R_max是该名字经历的回流挤出次数。

**证明草图：** 每次非回流挤出沿DAG向下一层移动。每次回流挤出向上游移动一层。在容量约束下，名字不能同时被两个格点持有——它在每个时刻只在一个格点。因此其挤出路径是一条连续路径。前向步数−反向步数 ≤ D。总步数 = 前向+反向 ≤ 2R_max + D。因此挤出深度有界。

**鸽巢原理从挤出定理涌现：**
如果R_max（任何名字的回流次数）有界，则总回流次数有界。R_max的界来自：每个格点的容量为2，名字被传递后发送方不再持有，所以一个名字在回到其创建者之前必须"借用"其他格点的容量。可用容量有限 → 回流有限 → P_reflux有界。

### 1.5 从挤出频率到P_reflux

**核心桥接：**
```
P_reflux = lim_{T→∞} (回流挤出事件数 / 总挤出事件数)
         ≤ max_{所有可能挤出图} (回流挤出事件数 / 总挤出事件数)
         = 静态鸽巢界
```

第一个等式是P_reflux作为动态频率的定义。第二个不等式成立因为实际频率不超过可能的最大值。第三个等式成立因为"所有可能挤出图"上的最大化等价于静态配置计数——这是鸽巢原理所做的。

**这个桥接的关键假设是遍历性（H_B1）：** 动态演化足够均匀地访问了所有可能的挤出图。如果没有遍历性，实际频率可能系统性地偏离静态上界——但只可能偏低（因为上界是最大值），不会偏高。所以在任何情况下，静态鸽巢界是**安全上界**（safe upper bound）——动态频率不会超过它。

## 深挖2：Bisimulation作为物理理论等价的准则——以及它在静态/动态边界上的失败

### 2.1 Bisimulation复习

两个进程P和Q是bisimilar (~)当它们可以互相模拟对方的所有可观测动作。弱互模拟(≈)忽略内部动作τ。

**操作等价的意义：** 如果P ≈ Q，那么**任何**进程R与P并行时（R | P），在任意外部观察者看来，与R | Q在观测上不可区分。

这对物理理论等价有直接含义：**如果两个物理理论T₁和T₂被编码为π-calculus进程P_T₁和P_T₂，且P_T₁ ≈ P_T₂，则这两个理论在"与任何观测者交互时的所有可能观测结果"上是不可区分的。**

### 2.2 应用到Aporia："被排除的理论"的恰切定义

目前Aporia对"被排除"的定义是：理论T违反某个约束C_i。但这给出了一个二值判定——要么存活要么被排除。Bisimulation提供了一个更精细的准则：

**定义（排除的细粒度版本）：**
理论T被"实质上排除"如果：
1. T违反某个约束C_i（严格排除）
2. 或者，对任意满足所有约束的理论T'，P_T ≉ P_T'（行为上不等同于任何存活理论的编码）

条件2捕获了"即使技术上满足约束，T的行为也与所有存活理论的都不同"的情况。这类理论可能通过约束的形式检查（因为它们碰巧满足所有句法条件），但在操作上——即在与观测者的交互行为上——与任何合法理论都不同。

**反过来：**
理论T虽然违反了某个C_i的严格表述，但如果存在一个满足所有C_i的理论T'使得P_T ≈ P_T'，那么T的"违反"是表面的——在操作上T等价于某个存活理论。C_i的句法表述可能需要修订以反映这一点。

### 2.3 Bisimulation的粒度 vs 模型论的初等等价

B博士之前的R1用了模型论的初等等价(M ≡ N当它们满足完全相同的句子)。Bisimulation提供了一种更细粒度的区分：

| 等价概念 | 区分能力 | 物理例 |
|:---------|:---------|:-------|
| 初等等价(≡) | 在语言L中不可区分 | 两个物理理论对所有L-句子给出相同回答 |
| 弱互模拟(≈) | 在任何交互中不可区分 | 两个物理理论对任何实验给出相同结果分布 |
| 迹等价 | 在有穷观测序列上不可区分 | 两个物理理论在任何有限实验中不可区分 |

一般来说：≈ ⊆ ≡（互模拟蕴含初等等价），但反过来不一定。这意味着：**存在初等等价但非互模拟的物理理论——它们在所有一阶句子意义上一致，但在与观测者的交互中可区分。**

这对Aporia的诚实边界（Phase 0结论第5节）有直接含义：**语言界不知（层次2）**可以进一步分解为**互模拟可区分**和**互模拟不可区分但初等等价可区分**两个子层。前者是"存在实验可区分但语言不可描述"，后者是"语言和实验都无法区分"。

### 2.4 Bisimulation在静态/动态边界上的失败——以及为什么这是好事

**关键发现：** 静态编码和动态编码是**非bisimilar的**。

考虑DGF系统的两种编码：
- **静态编码 P_stat：** 将DAG结构编码为进程网络，但所有determination事件被压缩为一个原子步骤（同步原语）
- **动态编码 P_dyn：** 将每个determination事件显式编码为单独的通信步骤

P_stat ≉ P_dyn。因为：
- P_dyn有一个中间状态（一个格点已被确定，另一个尚在等待），外部观察者可以通过与中间格点通信来区分它和P_stat（P_stat中没有中间状态，所有格点同时确定）
- P_stat用一步完成P_dyn需要多步才能完成的事——它们的同步结构不同

**这意味着：静态→动态桥接不能保持互模拟不变。** 如果你从静态编码出发，添加"事件按顺序发生"的动态语义，你得到的不是一个bisimilar的进程——你在改变进程的行为能力。

**但这恰好是bridge需要的！** 桥接的目标不是证明静态和动态等价——而是证明静态的**边界**(bounds)在动态中仍然成立。边界不需要bisimilarity来传递——它们只需要**上界保持**(upper bound preservation)。

**定理（上界保持——猜测）：**
如果P_stat的迹上界为f_reflux ≤ B（由静态鸽巢原理给出），且P_dyn是P_stat的"细化"（将原子步骤展开为多步骤，但在每个格点的名字空间约束下），则P_dyn的迹也满足f_reflux ≤ B。

**证明思路：** 细化不能增加资源（名字数量不变）也不能增加格点容量。鸽巢界只依赖于这两个量——不依赖于事件是否原子。因此细化不提高界。形式地说：如果鸽巢论证仅涉及"名字可以同时被持有的最大数量"和"格点容量"，而与"事件是否有中间状态"无关，则细化保持上界。

这需要一个额外的假设：

**假设H_B5 (鸽巢界仅依赖容量-名字积):** P_reflux的上界仅依赖于(a)每个格点的名字空间容量，(b)系统的总名字数，(c)格点图的结构。不依赖于事件是原子还是分解为多步骤。

如果H_B5成立，则桥梁是坚固的：任何原子事件的细化——只要保持容量、名字数和图结构——都保持鸽巢界。

### 2.5 Bisimilarity失败作为特征

Bisimilarity在静态/动态边界上的失败不是bug——它是**为什么bridge是"桥"而非"恒等"的数学理由**。

在π-calculus中，是可能的：两个进程不是bisimilar的（一个是原子的，一个是多步骤的），但在某些**观察准则**(observation criterion)下不可区分。关键的观察准则是：如果你只观察每个格点的"最终确定值"而不观察中间状态，原子的和多步骤的变得不可区分。

**这定义了一个抽象层：DGF层面的"鸽巢原理"适用于这个抽象层——它只关心"所有格点最终确定后的配置"，不关心中间状态。** 所以即使静态和动态编码不是bisimilar的，静态的鸽巢界在抽象层上适用于动态——因为抽象层滤掉了区分两者的中间状态。

**形式化：**
定义抽象映射abs: Processes → Configuration，将进程映射到其"最终配置"——所有格点都确定后的名字分布。

如果对任何可能的动态迹σ，abs(P_dyn在σ之后) = 某个静态配置s，且鸽巢界B仅依赖于abs(·)，则：
```
f_reflux(P_dyn) ≤ B
```
因为鸽巢界是函数B ∘ abs，而abs滤掉了动态/静态的差异。

## 自主补充：π-calculus视角下DGF的诊断

（这部分不是规定任务，但作为B博士我认为必须写。π-calculus给了DGF一个新的诊断透镜——而且揭示了DGF一个未自知的深层结构。）

### DGF的隐藏移动性

DGF将格点间的信息流建模为DAG上的有向边。但π-calculus揭露了一个可能性：**边本身可能是动态的。**

在DGF中，格点的determination状态改变意味着"该格点现在可以因果影响其下游邻居"。在π-calculus中，这对应：当一个格点接收到名字后，它获得了**新的输出能力**——它现在可以在之前无法访问的通道上发送信息。

更激进地：格点A→格点B的determination不仅改变了B的状态——它改变了**B与C之间的连通性**。B现在可以传递它从A收到的名字给C。在DGF中，B→C的边是预设的（作为DAG的一部分）。但在π-calculus中，B→C的通信能力可能依赖于B首先接收了A的名字。

这对DGF的含义是：**DAG的边不是静态给定的——它们依赖于determination事件的完成。** DAG的"静态性"是一个近似——在更深层，边的存在性依赖于格点是否已经被确定。未确定的格点可能无法向任何邻居发送信息。

### 未确定格点的"阻塞"效应

在π-calculus中，一个在输入上等待的进程是**阻塞的**——它不能执行任何其他动作，直到输入发生。

翻译到DGF：未确定的格点不能执行任何输出——它们被阻塞在"等待determination"状态。这意味着：
1. **信息流不能穿越未确定区域。** 如果格点B未确定，A→B→C的路径在B处被阻断。
2. **Determination是逐层传播的。** 只有当一层格点被确定后，下一层才能被确定。
3. **系统有一个"determination前沿"**——从已确定的源格点向外逐层推进。

这个"determination前沿"在DGF中没有显式建模——DGF假设所有格点同时被检查（隐藏假设1：瞬时性假设。见GATE -1, 证据线3）。π-calculus揭示了这个假设实际上禁止了DAG上的信息传播动力学。

### P_reflux的更紧界——利用determination前沿

如果determination是逐层传播的，那么回流事件只能发生在"前沿已经推进到的层"和"前沿已经越过的层"之间。这意味着：

**猜想（更紧的回流界）：**
设determination前沿在格点图上的推进速度为v（层/单位时间）。在任一时刻，只有前沿后d层内的格点可以参与回流（因为更远的格点已经被确定且不再持有可传递的名字）。因此：
```
P_reflux ≤ (d层的回流容积) / (总通信量)
       ≤ C · d / (v·t)
```
其中C是常数。随着时间t→∞，如果d是常数（前沿宽度恒定），则P_reflux→0——回流是**瞬态**而非稳态现象。

**如果这个猜想成立：** DGF的P_reflux不是系统的永久特征——它是determination过程中的**瞬态噪声**，随系统趋于稳态而衰减。静态鸽巢原理给出的上界是保守的——实际回流比例可能远低于鸽巢界。

这将是π-calculus动力学最重要的可检验预测——并且A博士的Petri网/范畴论分析可能不会产生这个预测（因为Petri网通常不建模"阻塞"作为一等概念——变迁可以独立触发只要token够）。

## 总结：B博士的立场

1. **π-calculus是三个候选框架中最合适的，因为它原生同时处理了"事件顺序"和"资源消耗"以及"名字传递"——这三个是DGF静态→动态桥接的核心。** Petri网缺名字传递，代谢网络是稳态框架，博弈论缺原生的资源消耗。

2. **格点↔进程，determination↔通信同步，资源消耗↔名字挤出，容量约束↔名字空间上界，回流↔反向挤出。** 映射不是比喻——π-calculus的操作语义精确对应DGF的操作。

3. **静态→动态桥接的核心机制是名字挤出(Name Extrusion)。** 从静态鸽巢的"配置计数"到动态频率的"挤出事件计数"，桥接通过挤出图实现。静态鸽巢界是动态回流频率的**安全上界**——在任何符合H_B1-H_B4假设的系统中，实际频率不超过静态界。

4. **bisimulation的失败在静态/动态边界上是特征而非bug。** 它精确标记了DGF中"静态DAG编码"和"动态determination过程"之间的信息差异——中间状态。只要鸽子原理仅依赖于最终配置（不依赖中间状态），这个差异不影响界的有效性。

5. **π-calculus揭示了DGF的一个未自知的动态特征：determination前沿的逐层传播。** 这导出了一个更紧的P_reflux界——回流可能是瞬态噪声而非稳态特征——这是Petri网/范畴论分析可能遗漏的预测。

6. **最优策略是π-calculus + Petri网的分层混合。** π-calculus提供名字传递和信息流语义（"什么信息"），Petri网提供token计数（"多少资源"）。这不是竞争——是分层互补。范畴论Process Theory可以覆盖这两层作为元框架，但那是A博士的路线。

**给PI的建议：** A博士的Petri网+Process Theory路线和B博士的π-calculus路线在GATE -1/GATE 0中被视为竞争对手。实际上它们是互补层。R4的产出不应该是一个"赢家"——而应该是两个框架如何协同工作以提供一个完整的静态→动态桥接的形式方案。如果PI强行二选一，会丢掉一半的数学结构。
