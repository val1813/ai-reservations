# LP29-C2T-S2-R1 contradiction deepening

Date: 2026-06-05

## Surface Contradiction

A: A proof-carrying schema/oracle is enough to close exact `O_s` baseline admission as protocol-ready.

B: A schema/oracle can still be empty documentation unless it is executed against fixtures and returns terminal statuses.

## Five Whys

1. Why is `O_s` not a naked scalar?

Because the same numeric value can arise from different structures, pair populations, raw sums, and normalizations.

2. Why did the proof-carrying contract help?

Because it makes the missing identity conditions explicit: F01-F22 payload fields and P0-P8 predicates.

3. Why is the contract still not enough?

Because a contract can be internally coherent but unexecuted. It can specify what should happen without proving that the project machinery actually emits the expected statuses.

4. Why does execution matter scientifically?

Because the danger is silent promotion: DOI-only or context-only evidence being accepted as exact `O_s`. Only negative fixtures and validator outputs can prevent that operationally.

5. Why is this deeper than implementation hygiene?

Because it defines the boundary between a scientific admissibility rule and a prose norm. A rule that cannot reject bad payloads is not an admissibility rule.

## Deep Contradiction

The deeper conflict is:

> specification-as-argument vs validator-as-scientific-gate.

If specification-as-argument is enough, the project can close with schema/oracle prose. If validator-as-scientific-gate is required, then the next real unit is an executable validator with fixtures.

## Current Deepest Answer

S2-R1 closes as protocol-ready, not validator-executed.

The next candidate must build the validator or explicitly remain at the protocol artifact level.
